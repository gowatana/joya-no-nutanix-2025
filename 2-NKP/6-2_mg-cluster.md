# 6-2. 管理クラスタ

Kubernetesクラスタ群を管理するためのKubernetesクラスタです。このクラスタから、アプリケーション展開用のKubernetesクラスタをプロビジョニングし、それらのノード追加/削除・アップデートといったライフサイクル管理も実施します。

NKPにおいては、Web UIの提供や独自のフリート管理についても、このクラスタが受け持ちます。また、単一のクラスタのみが必要な環境では、このクラスタを「Self-Managed クラスタ」として扱い、ワークロードの展開に利用できます。


## NKPによってAHVに展開されるKubernetesクラスタ

NKPによってAHVにプロビジョニングされるKubernetesクラスタは、デフォルトでもアプリケーションを展開するために必要なものがインストールされます。プラットフォームによってデフォルト構成は異なりますが、例としてAHVに展開したクラスタでは次のような構成となります。
* アップストリームのKubernetesが利用されている。
* ワーカーノードはノードプールとして追加され、スケールアウト・スケールイン可能になっている。
* ロードバランサーとしてMetalLB、IngressコントローラーとしてTraefikがインストールされている。
* Container Network Interface（CNI）としてCiliumがインストールされている。
* Container Storage Interface（CSI）としてNutanix CSI Driverがインストールされている。
* あとはNKPによるフリート管理（kubefedを利用）とプラットフォームアプリケーション（cert-manager、cluster-autoscalerなど）が導入されている。

## Kubernetesクラスタのコントロール プレーンとワーカー ノード
Kubernetesクラスタのノードには、制御プレーンとワーカーの2つに分けられます。NKPでクラスタをプロビジョニングする際には、制御プレーンとワーカーそれぞれについて、ノード数、CPU/メモリ/ストレージのスペック、展開先のNutanixクラスタ、接続するネットワークなどを指定できます。

また、ワーカー ノードはノード プールとして作成されており、ノード数の増減（スケールアウト・スケールイン）、用途別のワーカー追加（GPUノードプールなど）といった要件にも柔軟に対応できます。

なお、ライセンスがカウントされるのはワーカー ノードのCPUコア数であり、コントロール プレーン ノードのCPUコアは含まれません。
